# PedroDevTools

Локальная панель инструментов. Версия 3.0: апскейл видео **и фото** на
нейросетях плюс 15 инструментов для видео, фото, музыки и конвертации —
17 вкладок, собранных в 4 группы.

Всё считается на твоей машине: файлы никуда не уходят, интернет нужен только
при первом скачивании моделей.

## Режимы

- **Простой** (по умолчанию): файл → цель (720p/1080p/4K/×2/×4) → модель →
  запуск. Движок, кодек и остальное подбираются сами.
- **Расширенный**: все настройки — движок, масштаб в пикселях и процентах,
  кодек, CRF/битрейт, чанки, потоки, тайлы, TTA, диапазон.

## Темы

Две, переключаются кнопками в шапке, выбор помнится в браузере. Если тема ещё
не выбрана, берётся системная настройка, иначе — тёмная.

Шестым цветом каждой темы (в тёмной он значился как «детали») красится полоса
прогресса и рамки предупреждений.

| | фон | панели | текст | акцент | тревога | прогресс |
|---|---|---|---|---|---|---|
| Светлая | `#F4F1EA` | `#FFFFFF` | `#1A1A1A` | `#4A7C59` | `#A93F42` | `#D4A373` |
| Тёмная | `#1C1C1C` | `#2A2A2A` | `#EAEAEA` | `#588157` | `#BC4749` | `#E0A96D` |

Тема ставится в `<head>` до отрисовки, поэтому при перезагрузке нет вспышки
чужого цвета.

## Группы вкладок

Боковая панель — не плоский список, а группы со счётчиком. Группы независимые:
клик по заголовку раскрывает или сворачивает только его, остальные не трогаются,
так что можно держать открытыми сразу несколько папок. Состояние запоминается,
по умолчанию открыты все.

| Группа | Вкладок | Что внутри |
|---|---|---|
| **Видео** | 9 | апскейл нейросетью, размер, компрессор, скорость, нарезка, поворот, видео→аудио, видео→GIF, видео+аудио |
| **Фото** | 3 | **апскейл нейросетью**, размер, компрессор |
| **Аудио** | 3 | компрессор, громкость (в т.ч. нормализация EBU R128), нарезка |
| **Файлы** | 2 | конвертер «всё во всё», метаданные |

## Размер и разрешение — одна вкладка

Отдельных вкладок «Размер» и «Разрешение» больше нет, есть одна с галочкой
**«Сохранять пропорции»**:

- галочка стоит — задаёшь любую сторону (или обе), вторая считается сама,
  кадр не искажается;
- галочка снята — ровно `ширина × высота`, кадр растянется или сплющится,
  зато попадёт в нужное разрешение точно. Ноль в любой из сторон при снятой
  галочке означает «взять размер исходника».

Одинаково работает для видео и для фото.

## Нарезка мышкой

У «Нарезки видео» и новой «Нарезки музыки» есть полоса монтажа вместо
обязательных цифр:

- края выделения тянутся мышкой (или пальцем — `touch-action` отключён);
- клик по самому выделенному куску двигает его целиком;
- клик по пустому месту ставит начало в эту точку;
- кнопки «Короче», «Длиннее», «К началу», «До конца» — типичные подгонки;
- рядом идут точные значения начала, конца и длины, они же пишутся в поля
  `start` / `duration` — если вписать секунды руками, полоса подстроится сама;
- у видео над полосой показывается кадр из середины выделения, обновляется
  при перетаскивании (через полсекунды, чтобы не дёргать ffmpeg на каждый
  пиксель; кадр кэшируется в одном файле и не засоряет `tmp`).

## Предпросмотр загруженного файла

Видео после загрузки показывается **плеером**, а не одним кадром: файл
отдаётся с `inline`-типом и без `Content-Disposition: attachment`, иначе
браузер его скачивал бы вместо воспроизведения. Картинки показываются
картинкой, треки — плеером. В панели апскейла и в панели инструментов
поведение одинаковое.

## Апскейл фото

Отдельная вкладка «Апскейл фото» — тот же движок и те же модели, что и у видео,
но без чанков: одна картинка уходит в движок целиком, точность размера
доводится ресайзом Lanczos.

- Движок: авто / GPU Real-ESRGAN / GPU SRMD / процессор.
- Масштаб: во сколько раз, по длинной стороне или точные пиксели. Перед
  запуском показывается строка вида `1920×1080 → 3840×2160 (×2)`.
- Модель скачивается сама при первом запуске — отдельная кнопка «скачать» не
  нужна.
- Формат на выходе: как в исходнике, JPG, PNG или WebP, качество 1–100.

Для людей нативный ×2 даёт SRMD; `realesr-general-x4v3` — только ×4, поэтому
запрос ×2 через неё дотянется ресайзом.

## Превью результата

Готовый файл показывается в интерфейсе, а не только уходит в «Скачать»:
видео в `<video>` с управлением, аудио в `<audio>`, фото как картинка. Рядом —
размер, разрешение, кодек, длительность и битрейт результата. MKV и AVI
браузер не играет: для них выводится подсказка открыть файл в плеере.

Исходник тоже виден сразу после загрузки: первый кадр для видео, сама картинка
для фото, плеер для музыки.

## Запуск

Двойной клик по `run.bat`. Скрипт создаст `.venv`, поставит зависимости,
поднимет сервер и откроет <http://127.0.0.1:8756>.

Требования: Python 3.11+ и `ffmpeg` с `ffprobe` в PATH.

Запуск вручную:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python server\main.py
```

## Как устроен апскейл видео

Видео обрабатывается **чанками**, а не целиком. Для каждого чанка: ffmpeg
распаковывает кадры в PNG → движок Real-ESRGAN увеличивает каждый кадр →
ffmpeg кодирует чанк в отдельный файл → в конце чанки склеиваются через
concat, и аудио подмешивается из исходника.

Промежуточные кадры каждого чанка удаляются сразу после кодирования, поэтому
расход диска не растёт с длиной ролика. Если места мало, размер чанка
уменьшается автоматически — об этом появится запись в консоли.

Число чанков считается через `ceil`, а не `round`: округление вниз однажды
молча выкидывало хвост ролика. Результат длиннее 90 % заказанного отдаётся,
короче — считается ошибкой, обрезок не отдаём.

Прогресс идёт по кадрам: сколько обработано, сколько всего, скорость и ETA.
Работающую задачу можно отменить — процесс движка завершается, временные
файлы удаляются.

## Движки

| | Движок | Масштабы | Скорость |
|---|---|---|---|
| **GPU** | `realesrgan-ncnn-vulkan` | ×2, ×3, ×4 | быстро |
| **SRMD** | `srmd-ncnn-vulkan` | ×2, ×3, ×4 | в ~2.5 раза быстрее Real-ESRGAN |
| **CPU** | `realsr-ncnn-vulkan` (`-g -1`) | только ×4 | в десятки раз медленнее |

Важное ограничение, проверенное на четырёхцветной мишени: ключ `-s` обязан
совпадать с родным масштабом сети. `-s 2` на ×4-модели даёт кадр верного
размера, но с убитым цветом (выживает только красный канал). Поэтому пайплайн
всегда передаёт `-s`, равный масштабу модели, а точный размер доводит ресайзом
Lanczos через ffmpeg — цвета целы. Нативные масштабы: animevideo — ×2/×3/×4
своими сетями, SRMD — ×2/×3/×4 своими, остальное — только ×4.

Список устройств определяется из реального вывода движка, а не из
абстрактного Vulkan. Если GPU недоступен, в интерфейсе он показан
отключённым с причиной, а апскейл уходит на процессор.

У двух движков разные соглашения об именах моделей, это учитывается:

- `realesrgan-ncnn-vulkan` получает `-m <каталог> -n <имя>` и читает
  `<каталог>/<имя>.param`;
- `realsr-ncnn-vulkan` получает `-m <каталог> -s 4` и требует, чтобы в имени
  каталога было `models-DF2K` или `models-DF2K_JPEG`, а файлы лежали как
  `x4.param` / `x4.bin`;
- у `srmd-ncnn-vulkan` ключ `-n` — это уровень шума (`-1` без денойза, `3`
  с денойзом), а не имя модели. Путать нельзя.

## Модели

Скачиваются по требованию, с прогрессом, файлы кладутся в `bin/`.

GPU (`realesrgan-ncnn-vulkan`):
- `realesr-general-x4v3` — сбалансированная, дефолт
- `AnimeSharp` ×4 — аниме с резкими штрихами
- `realesrgan-x4plus` — качество, фотореализм
- `realesrgan-x4plus-anime` — аниме-иллюстрация
- `realesr-animevideov3` ×2 / ×3 / ×4 — лёгкие, для аниме-видео

CPU (`realsr-ncnn-vulkan`):
- `DF2K` — базовая модель ESRGAN
- `DF2K_JPEG` — та же, обученная на JPEG-артефактах

SRMD (`srmd-ncnn-vulkan`):
- `srmd-x2` / `srmd-x3` / `srmd-x4` — нативные сети для реальных фото и людей
- `srmdnf-x2` / `srmdnf-x3` / `srmdnf-x4` — те же с денойзом

`realesr-general-wdn-x4v3` в ncnn-виде недоступна: в официальных релизах есть
только `.pth` для PyTorch, конвертации в `.param`/`.bin` там нет.

Пробовали RealESRGAN_x2plus в ncnn (конверсия `bpawnzZ/Real-ESRGAN-x2plus-NCNN`):
не взлетел — в `.param` слой `MemoryData`, которого нет в ncnn 2022 года
(«layer MemoryData not exists or registered»). Плюс вход там `input`, а бинарь
хочет `data`. Вернуться к нему можно только с новым бинарём.

## Про разрешение

Модели увеличивают только целыми кратными. Режим «Пиксели» позволяет задать
любую цель — 1366×768 или 1080×1440. Тогда берётся ближайший доступный апскейл
своей сетью, а разница доводится ресайзом Lanczos на этапе кодирования.
Интерфейс честно пишет об этом жёлтой строкой, потому что ресайз — это не
нейросеть. Зелёная строка «попадает точно» означает, что весь путь — нейросеть
без довесков: например, SRMD ×2 при цели ровно ×2.

## Про кнопку запуска

Кнопка никогда не гаснет молча: под ней всегда строка-причина («загрузите
видео», «качаю модель — запустится само»). Если модель не установлена, клик
докачивает её и запускает задачу автоматически.

Один физический клик не должен превращаться в три запуска, поэтому событие
помечается флагом и повторные обработчики его игнорируют. Кроме того, при
загрузке страницы проверяются повторы `id` в разметке: именно дубль
`id="start"` однажды убивал кнопку — `getElementById` возвращал поле ввода.

## Структура

```
server/   main.py ffmpeg.py upscale.py imgup.py media.py models.py
          devices.py jobs.py config.py
web/      index.html  app.js  style.css  PedroDevLOGO.png
bin/      движки и модели (создаётся автоматически)
output/   готовые файлы
tmp/      промежуточные кадры и тесты, чистится после задач
presets/  настройки и пользовательские пресеты
```

`server/main.py` отдаёт статику с `Cache-Control: no-store` — закэшированный
HTML больше не может объяснить, почему интерфейс ведёт себя не так, как на диске.

## Про кодировку файлов

PowerShell 5.1 читает файл без BOM однобайтовой кодировкой (у русской Windows
это CP1251) и пишет обратно как UTF-8. Русский текст после этого превращается
в «Р°РѕС‚РѕРІ», и **молча ломает код**: как выяснилось, испорченный комментарий
рядом с `.format()` однажды уронил целую операцию.

Отсюда правило: файлы проекта править только инструментами, которые пишут
UTF-8, и не использовать `Set-Content`/`Out-File` без `-Encoding UTF8` на
исходниках с русским текстом. Проверка: `python tmp/scan_mojibake.py`
(с `--fix` — чинит построчно; строки с легитимными символами «→», «×», «°»
обратно не кодируются и остаются нетронутыми).

## Что стоит знать

- **CPU-режим на этой машине медленный.** Замер: 640×360, ×4 — около 50 секунд
  на кадр. Ролик на минуту в 1080p — это часы работы. Для быстрых результатов
  нужен GPU.
- **Radeon RX 550X** видна как Vulkan-устройство, но это Polaris, и у
  `realesrgan-ncnn-vulkan` на нём есть известные проблемы с чёрными кадрами.
  Первый кадр стоит проверить глазами через превью «до/после».
- **ffmpeg** на этой машине — сборка от 2025-12-07, версия определяется
  автоматически при старте и показывается в панели состояния короткой строкой.
- Результат сразу кодируется с CRF, поэтому качество исходника выше не
  поднимется — апскейл добавляет разрешение, а не детализацию.
